# 拦截器 Interceptor

## 解决什么问题？

以登录业务为例：后端有大量功能需要执行前先校验登录状态（没有登陆不让用），但是如果单独给这些功能写独立的校验就很复杂，不仅代码量巨大，也无法保证一致性；

SpringBoot提供了一个拦截器机制，可以在多个Controller前面接一个固定的处理逻辑



## 怎么实现？

### 代理模式

使用代理模式实现（动态代理）

1. 定义一个接口，接口描述一个行为`behavior()`
2. 定义一个核心的生产者类A，实现该接口
3. 定义另一个代理类Proxy，也实现该接口，但真正负责执行核心代码的是A的`a.behavior()`，Proxy中的`behavior()`会在`a.behavior()`执行之前、之后添加一些额外的操作

```java
public interface Behavior
{
    public abstract void behavior();
}

public class A implements Behavior
{
    public void behavior()
    {
        System.out.println("真正的核心逻辑");
    }
}

public class Proxy implements Behavior
{
    private Behavior source;
    
    public Proxy(Behavior source)
    {
        this.source = source;
    }
    
    // 重载behavior
    public void behavior() {
		before();
		try{
			source.sell();
			after();
		} catch (Exception e) {
			unexcept();
		} finally{
			complete();
		}
	}
    
    //前置通知
	public void before(){
		System.out.println("打广告");
	}
	//后置通知
	public void after(){
		System.out.println("送货上门");
	}
	//例外通知
	public void unexcept(){
		System.out.println("鞠躬道歉");
	}
	//最终通知
	public void complete(){
		System.out.println("好评返现");
	}
    
}
```



### JavaSpring中的写法

1. 编写`拦截器类`：实现`HandlerInterceptor`接口，该接口中包含`preHandle` `postHandle` `afterCompletion`三个方法，分别对应前置处理、后置处理、最终处理

2. 使用`@Component`把`拦截器类`注册给Spring管理

   ```java
   @Component
   public class TokenInterceptor implements HandlerInterceptor {
   
       @Override
       public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception 
       {
           // 进行一些业务
           return true;
       }
   
   }
   ```

3. 编辑`配置类`，让拦截器生效

   ```java
   // 1. 在工程的根目录下编写该java类
   // 2. 实现 WebMvcConfigurer 接口
   // 3. 使用 @Configuration 注册
   // 4. 使用 @RequiredArgsConstructor 注入依赖，把 拦截器类注入
   // 5. 重载 addInterceptors(InterceptorRegistry registry) 方法
   // 6. 不必关心 registry 这个参数是怎么传递进来的，这是框架的工作
   // 7. 在 addInterceptors 函数里使用 addInterceptor注册拦截器
   // 8. 使用 addPathPatterns excludePathPatterns 设置拦截器
   @Configuration
   @RequiredArgsConstructor
   public class InterceptorConfig implements WebMvcConfigurer {
   
   	private final TokenInterceptor interceptor1;
   
   	@Override
   	public void addInterceptors(InterceptorRegistry registry) {
   		//注册拦截器 同时配置拦截路径 拦截/**（全体路径）,排除/login和/regist
   		registry.addInterceptor(interceptor1)
   				.addPathPatterns("/**")
   				.excludePathPatterns("/login")
   				.excludePathPatterns("/regist");
   	}
   }
   
   ```
   
   

# 令牌 Token

## 解决什么问题？

如果没有token，那么后端不知道现在发起请求的这个用户，到底有没有登录...总不能让用户切换一个页面就输一次用户名密码校验一下吧...



## Token结构

token分为三部分：

其中前两部分都是Base64URL编码的json明文

第三部分是将前两部分的编码结果拼接，用指定的算法（如 HMAC-SHA256）和密钥进行签名，得到二进制结果，再进行 Base64URL 编码。

```shell
# 1. Header
{"alg": "HS256", "typ": "JWT"}
# 2. Payload
{"sub": "login", "user": "zhangsan", "exp": 1777888800}
# 3. Signature
HMACSHA256(
    base64UrlEncode(header) + "." + base64UrlEncode(payload),
    secret
)
```

2. 编写Token的工具类

   ```java
   public class TokenUtil {
   
   	private static final String SECRET_KEY = "neusoftbsd";// 密钥，签发token和验证token时都用这个
   	private static final String ISSURE = "neusoft.bsd";// 签发者标识，告诉别人token是哪个组织签发的
   	private static final int EXPIRE = 86400000; // Token有效时间，单位ms
   
   	//根据用户account生成令牌（也可以利用其他数据生成令牌）
       // Header不用考虑
       // Payload要自己设置
       // Signature不用考虑
   	public static String getToken(String account) {
   		Map<String, String> payload = new HashMap<String, String>();
   		payload.put("user", String.valueOf(account));
   		String token = getJWTWithHMAC256("login", payload, SECRET_KEY);
   		return token;
   	}
   
   	//验证令牌，返回字符串类型的用户account
   	public static String verifyToken(String token) {
           // 验证 签名正确（用SECRET_KEY重新算一次token）
           // 能对上就说明token是对的
   		if(verifyTokenWithHMAC256(token, SECRET_KEY)) { 
   			DecodedJWT decode = JWT.decode(token); // 解码获得的是Payload部分
   			String account = decode.getClaim("user").asString();
   			Date date = decode.getExpiresAt();
   			Date currDate = new Date(new Date().getTime());
   			if (currDate.after(date) ) {
   				return null;
   			}else{
   				return account;
   			}
   		}
   		return null;
   	}
   	
   	//内部加密使用
       // 用来算token的
   	private static String getJWTWithHMAC256(String subject, Map<String, String> payload, String secret) {
   		Algorithm al = Algorithm.HMAC256(secret);
   		JWTCreator.Builder token = JWT.create();
   		token.withIssuer(ISSURE);
   		token.withSubject(subject);
   		token.withExpiresAt(new Date(new Date().getTime() + EXPIRE));
   		Set<String> ks = payload.keySet();
   		for(String key : ks) {
   			token.withClaim(key, payload.get(key));
   		}
   		return token.sign(al);
   	}
   	
   	// 内部解密使用
   	private static boolean verifyTokenWithHMAC256(String token,String secret){
   		try {
   			Algorithm al = Algorithm.HMAC256(secret);
   			Verification v = JWT.require(al);
   			v.withIssuer(ISSURE);
   			JWTVerifier ver = v.build();
   			ver.verify(token);
   			return true;
   		}catch (Exception e) {
   			return false;
   		}	
   	}
   
   }
   
   ```

3. 签发token

   这里分为两种情况：token可以被放在cookie、localStorage / sessionStorage中；根据不同的情况需要不同的处理

   ```java
   @RestController
   public class LoginController {
   
       // 情况1： token作为返回值，由客户端决定存入sessionStorage还是localStorage
   	@PostMapping("/login")   //直接下发token，客户端来选择存入sessionStorage还是localStorage
   	public ResponseResult login(@RequestBody LoginVO vo){
   		//利用vo连接数据库，验证账号密码是否正确（略）
   
   		//编排的假数据(验证通过)
   		if(vo.getAccount().equals("admin") || vo.getAccount().equals("haha")){
   			//下发Token
   			String token = TokenUtil.getToken(vo.getAccount());
   			//直接将token作为响应数据： 客户端通过操作将token存入存入sessionStorage或localStorage中
   			return ResponseResult.isOK(token);
   		}else{
   			return ResponseResult.notAuth("账号密码不正确");
   		}
   	}
   
   	// 情况2：token放在cookie中
       @PostMapping("/login2")  //通过response下发token，直接存入客户端的Cookie中
       public ResponseResult login2(@RequestBody LoginVO vo, HttpServletResponse response){
           //利用vo连接数据库，验证账号密码是否正确（略）
   
           //编排的假数据(验证通过)
           if(vo.getAccount().equals("admin") || vo.getAccount().equals("haha")){
               //下发Token
               String token = TokenUtil.getToken(vo.getAccount());
   
               //利用Cookie下发Token（要求：客户端必须是浏览器）s
               Cookie c = new Cookie("tokenX", token);
               response.addCookie(c);
   
               return ResponseResult.isOK(token);
           }else{
               return ResponseResult.notAuth("账号密码不正确");
           }
       }
   }
   ```

   

4. 校验token

   根据token存放于cookie还是sessionStorage\localStorage，也分为两种i情况

   

   ```java
   @Component
   public class TokenInterceptor implements HandlerInterceptor {
   
   	@Override
   	public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
   		//1. Cookie中存放
   		Cookie[] cs = request.getCookies();   //得到客户端全部的Cookie数据
   		String token = null;
   		for(Cookie c : cs){
   			if(c.getName().equals("tokenX")){
   				//找到了token
   				token = c.getValue();
   			}
   		}
   		//2. 本地存储（SessionStorage/LocalStorage），客户端会将token放入到请求的Header部分
   		String token = request.getHeader("token");
   
           
           // 处理token
   		if(token == null || token.isBlank()){
   			//过期了或没找到，抛出自定义异常，通过全局异常处理给客户端响应
   			throw new AuthException();
   		}
   		String account = TokenUtil.verifyToken(token);
   		if(account == null || account.isBlank()){
   			throw new AuthException();
   		}
   		return true;
   	}
   
   }
   ```
